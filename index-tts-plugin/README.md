# IndexTTS-2 语音朗读插件（DeepSeek Harness Web GUI）

把对话中 **agent 回复的正文**朗读出来（IndexTTS-2 / 优云智算 Modelverse API）。

- 官方 API 文档：https://www.compshare.cn/docs/modelverse/models/audio_api/ttts
- 现有技能版实现（参考）：`../skills/index-tts-compshare/`（Python CLI + 语音管理）

## 功能

1. **播放按钮**：在每条 agent 回复末尾的操作栏（点赞/点踩旁边）新增喇叭按钮，点击朗读该条回复的**正文**（text 块）。
   - 排除思考过程（reasoning 块）、工具调用（tool 块）、图片等非正文内容。
   - 每条回复独立可读；同一时间只播放一条，再点一次停止。
2. **设置页**：WebUI 设置 → 「语音朗读」。
   - API Key（优云智算控制台获取）
   - 上传音色（MP3/WAV，≤20MB；**本地校验时长 5-30 秒**，采样率 ≥16kHz 由平台校验）并设为当前音色；**源文件自动存入浏览器 IndexedDB**，平台音色 7 天过期后**自动用存档重新上传并更新所选音色 id**（设置页刷新音色列表时检测；播放遇 `invalid_voice_id` 等明确 400/404 错误也会触发一次自动续期；无存档则提示手动上传；同一音色 30 秒内不重复触发续期，避免平台列表同步延迟导致重复上传）。存档跨会话持久，仅用户手动清除站点数据才失效（已申请 `navigator.storage.persist()` 持久配额）。
   - 音色列表 / 刷新 / 删除；**下拉框中带「· 可续期」标记的音色表示浏览器存有其源文件、过期可自动续期**（标记随刷新/上传/删除实时更新；删除平台音色会同步清理浏览器存档）
   - 语速（0.25–4.0）、采样率（22050/44100/48000）、音量增益（0.1–10，留空为默认；保存前本地校验）
   - 「播放测试」**不走缓存**：每次真实调用 API 合成试听音频（用于验证当前 Key/音色/参数与网络是否可用），试听结果也不写入缓存。
3. **文本过滤**：朗读前自动清洗
   - 颜文字/装饰符号（`(๑•̀ㅂ•́)و✧` 等，逻辑移植自技能版 `text.py`）
   - emoji（Unicode Extended_Pictographic + 变体选择符/ZWJ/肤色）
   - 常见 markdown 语法（标题/粗体/斜体/代码/链接/列表/引用/表格分隔符等）
   - 保留 `～`/`~` 语气词
4. **分段合成 + 并发流水线（低首句延迟 + 段间无等待）**：清洗后超过 API 上限（600 字符）时，先按段落、再按句子（`。！？!?；;`）贪心切分，**块大小渐增 100 → 200 → 400 → 600…**（首段小=快速开播；前几段播放时间为后续大段合成留足提前量，避免「100 字段播完、600 字段还没合成好」的卡顿）。点击播放后**按段顺序并发合成（有界并发上限 2，按会话计）**，第一段一返回立刻播放，利用播放时间并行等待后续段。**段间预载**：当前段播放期间把下一段 URL 预载进第二个 `<audio>` 元素并 `load()` 解码（main/aux 按段交替），`ended` 时直接切到已就绪元素（被自动播放策略拦截时自动回退主元素），段间切换无人为延迟。
   > 段间若仍能听到停顿，来源是模型/API 合成的 WAV 自带停顿（IndexTTS 语句间自然停顿 + API 默认的分块间隔静音参数），不是插件添加的。
5. **浏览器音频缓存（内存，字节预算保护）**：以「请求参数字符串（model/input/voice/speed/sample_rate/gain **+ apiKey 指纹**）」为 key，把合成出的 blob URL 缓存在浏览器内存（`Map`，段数上限 60、**总字节上限 60MB**，超限按最旧淘汰并 `revokeObjectURL`）。命中时按 LRU 刷新为最新；淘汰时**跳过当前正在播放/预载的 URL**。**同一 key 的在途请求会去重**（并发调用复用同一合成请求，不重复 POST、不重复记账）。设置页**每秒实时显示「音频缓存：N 段 / X MB」**，每次合成也在浏览器控制台输出占用。重复播放同一段文本直接播缓存，不重复调 API；缓存仅存浏览器内存（刷新页面即清空），不往后端存。**停止/切换播放后，已在途的合成仍会完成并写入缓存（不浪费）；未开始的段不再启动（含不再发起新的重试请求——退避等待期间被停止也会中止重试）。**
6. **优先级重试**：合成请求按会话优先级退避——当前播放会话（high）对 429/5xx/网络错误/超时短退避（1s→2s→4s，重试最多 3 次、共 4 次尝试）优先重试；后台/残留会话（low）让路（4s→8s，重试最多 2 次），并在 429 限流冷却期（8s）内等待，把 API 额度让给当前播放。通用请求（列表/删除）重试 2s→4s→8s。**会话停止后不再发起新的重试请求**。每个会话独立 2 并发，多个会话并存时全局在途可能超过 2（符合预期）。其它 4xx（如 401 密钥错误）立即失败。重试延时使用插件 `timer` 服务的 `ctx.timeout`。

## 架构

```
┌─ 浏览器（code.client）────────────────────────────────────────┐
│ 设置页 settings.section「语音朗读」                              │
│ 播放按钮 conversation.chat.assistant-actions「朗读」             │
│    │ 经 useChat(messageId) 取该条回复 text 块 → 过滤 → 分段       │
│    ▼                                                            │
│ XMLHttpRequest 直连 https://api.modelverse.cn/v1               │
│   POST /audio/speech        (JSON → WAV arraybuffer)           │
│   GET  /audio/voice/list    (音色列表)                          │
│   POST /audio/voice/upload  (FormData multipart)               │
│   POST /audio/voice/delete  (JSON)                             │
└────────────────────────────────────────────────────────────────┘
        ▲ host.call('get-config' | 'set-config')
┌─ Host（code.host）─────────────────────────────────────────────┐
│ harness.handle 内存配置存储：apiKey / voiceId / voiceName /      │
│ speed / sampleRate / gain（含范围校验）                          │
└────────────────────────────────────────────────────────────────┘
```

- 网络全部在浏览器侧完成（CORS 已实测开放；GET/POST JSON/FormData 均验证通过）。
- 宿主仅保存配置（动态插件生命周期内有效，不引入持久化存储）。
- 浏览器半部不使用 `fetch`（动态沙箱禁用），统一用 `XMLHttpRequest`。

## 重新加载（动态插件）

当前版本以动态 Cordis 插件（`itts-2`）形式运行。重新定义时：

```js
// cordis_define
//   kind: "new" | { kind: "existing", pluginId: "itts-2" }
//   code.host   = host.js 的函数体内容
//   code.client = client.js 的函数体内容
// 然后 cordis_run(pluginId, packageId, mode: "run" | "update")
```

## 使用步骤

1. 打开 WebUI 设置 → 「语音朗读」。
2. 填入 API Key（https://console.compshare.cn 获取），点「保存设置」。
3. 上传一段 5–30 秒的参考音频（MP3/WAV）作为音色（自动设为当前音色），或从列表选择已有音色。
4. 回到对话，点击某条 agent 回复末尾的喇叭按钮即开始朗读；再点一次停止。

> 提示：配置保存在内存中，插件重启后需重新填写 API Key。
